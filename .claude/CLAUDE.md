# stackfoundry repository

This repo is a Claude Code **marketplace** (`.claude-plugin/marketplace.json`) with one plugin,
`plugins/stackfoundry/`. The plugin generates, for any repository, a grounded set of rulebooks and target profiles
that drive generic role agents and orchestrator skills. Read [`docs/design.md`](../docs/design.md) before changing
the architecture.

## Layout

- `plugins/stackfoundry/skills/<name>/SKILL.md`: skills. `agents/<name>.md`: generic role agents.
- `plugins/stackfoundry/reference/`: the method (layers, schemas, research procedure, examples, rulebook and
  tracker templates). Skills read it through `${CLAUDE_PLUGIN_ROOT}/reference/…`.
- `plugins/stackfoundry/scripts/stackfoundry.sh` + `scripts/stackfoundry/`: the helper CLI (Python 3.11+, standard library
  only, no network). `hooks/hooks.json`: the guard hooks.
- `plugins/stackfoundry/evals/`: `claude plugin eval` cases. `fixtures/`: scaffold scripts for eval repos.
- `tests/`: unittest suite. `docs/`: design and release notes.

## Non-negotiables

- **No technology content in the plugin.** Rules about a framework are researched at run time and cited in the
  user's repo. The plugin ships procedure and templates only.
- **Never name a real project's internals** in a skill, agent or template. Examples use neutral names
  (`api`, `desktop`, `web`) or placeholders.
- **Python helpers: standard library only, no network calls, JSON for data.** Every subcommand documents whether
  it writes, and the read-only ones never do.
- Authoring rules for skills and agents: [`.claude/rules/authoring.md`](rules/authoring.md). Documentation rules:
  [`.claude/rules/documentation.md`](rules/documentation.md) (generated by stackfoundry for this repo), plus: one home
  per fact here (architecture in `docs/design.md`, releases in `docs/release.md`, authoring in
  `.claude/rules/authoring.md`; others link), and `plugins/stackfoundry/CHANGELOG.md` is recorded under `Unreleased`
  in the change that makes an entry true.

## Checks before calling a change done

```sh
python -m unittest discover -s tests -t .
sh plugins/stackfoundry/scripts/stackfoundry.sh verify-plumbing plugins/stackfoundry
claude plugin validate --strict .
claude plugin validate --strict plugins/stackfoundry
```

## Git

Single branch: work on `main`. Release tags (`stackfoundry--v<version>`) and pushes are the owner's. The pre-commit
hook lives in `.githooks/` (`git config core.hooksPath .githooks`).

## stackfoundry

This repo's specialists are generated by the stackfoundry plugin. The repo profile is
`.stackfoundry/profile.md`; targets and their gates are in `.stackfoundry/targets.json`.

| Rulebook | Loads when editing | Covers |

| [language-python](rules/language-python.md) | any Python file | encodings, the 3.11 floor, subprocess and path handling across OSes |

| [app-model-python-cli](rules/app-model-python-cli.md) | the plugin's scripts and hooks | subcommand contract, the guard's hook contract, fail-open |
| [app-model-claude-code-plugin](rules/app-model-claude-code-plugin.md) | skills, agents, reference, hooks, plugin manifest | plugin components, tool grants, briefs, paths |
| [capability-claude-code-marketplace](rules/capability-claude-code-marketplace.md) | the marketplace manifest, the release doc | marketplace entry, versions, tags |
| [tooling-unittest](rules/tooling-unittest.md) | `tests/` | the unittest suite on the 3.11 floor and three OSes |
| [tooling-claude-plugin-eval](rules/tooling-claude-plugin-eval.md) | evals, fixtures | eval cases, graders, scaffolds |
| [tooling-github-actions](rules/tooling-github-actions.md) | `.github/` | workflow security, pinning, runners |
| [testing](rules/testing.md) | tests, fixtures, evals, test designs | oracles, assurance gate, flaky tests |
| [dependency-bumps](rules/dependency-bumps.md) | version pin files | classifying and applying bumps |
| [documentation](rules/documentation.md) | docs, `.claude/`, READMEs, CLAUDE.md | living vs snapshot docs, plans and specs |

Targets: `cli`, `plugin`.
