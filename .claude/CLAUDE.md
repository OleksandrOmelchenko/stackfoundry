# stackfoundry repository

This repo is a plugin **marketplace** with one plugin, `plugins/stackfoundry/`, for Claude Code (its source
layout) and, through generated files, Codex, GitHub Copilot, Cursor, Gemini CLI and Antigravity CLI. The plugin generates, for any repository, a grounded set of rulebooks and target profiles
that drive generic role agents and orchestrator skills. Read [`docs/design.md`](../docs/design.md) before changing
the architecture.

## Layout

- `plugins/stackfoundry/skills/<name>/SKILL.md`: skills. `agents/<name>.md`: generic role agents.
- `plugins/stackfoundry/reference/`: the method (layers, schemas, research procedure, examples, rulebook and
  tracker templates). Skills read it through `${CLAUDE_PLUGIN_ROOT}/reference/…`.
- `plugins/stackfoundry/scripts/stackfoundry.sh` + `plugins/stackfoundry/scripts/stackfoundry/`: the helper CLI
  (Python 3.11+, standard library only, no network). `plugins/stackfoundry/hooks/hooks.json`: the guard hooks.
- `.stackfoundry/`: this repo's own profile, dogfooding the plugin, including a repo extension
  (`.stackfoundry/extensions/`).
- **Generated, never hand-edited:** the other assistants' plugin files (`plugins/stackfoundry/plugin.json`,
  `com.*/`, `.cursor-plugin/`) and marketplaces (`.agents/plugins/`, `.github/plugin/`, `.cursor-plugin/`). Change
  the Claude source or `scripts/build_clients.py`, then run `python scripts/build_clients.py`. The mapping per
  assistant is `plugins/stackfoundry/reference/clients.md`.
- `plugins/stackfoundry/evals/`: `claude plugin eval` cases. `fixtures/`: scaffold scripts for eval repos.
- `tests/`: unittest suite. `docs/`: design and release notes.

## Non-negotiables

- **No technology content in the plugin.** Rules about a framework are researched at run time and cited in the
  user's repo. The plugin ships procedure and templates only.
- **Never name a real project's internals** in a skill, agent or template. Examples use neutral names
  (`api`, `desktop`, `web`) or placeholders.
- **Python helpers: standard library only, no network calls, JSON for data.** Every subcommand documents whether
  it writes, and the read-only ones never do.
- Authoring rules for skills and agents: [`.claude/rules/authoring.md`](rules/authoring.md). Documentation rules:
  [`.stackfoundry/rules/documentation.md`](../.stackfoundry/rules/documentation.md) (generated by stackfoundry for this repo; Claude Code loads its copy in `.claude/rules/`), plus: one home
  per fact here (architecture in `docs/design.md`, releases in `docs/release.md`, authoring in
  `.claude/rules/authoring.md`; others link), and `plugins/stackfoundry/CHANGELOG.md` is recorded under `Unreleased`
  in the change that makes an entry true.

## Checks before calling a change done

```sh
python -m unittest discover -s tests -t .
sh plugins/stackfoundry/scripts/stackfoundry.sh verify-plumbing plugins/stackfoundry
python scripts/build_clients.py --check
claude plugin validate --strict .
claude plugin validate --strict plugins/stackfoundry
```

## Git

Single branch: work on `main`. Release tags (`stackfoundry--v<version>`) and pushes are the owner's. The pre-commit
hook lives in `.githooks/` (`git config core.hooksPath .githooks`).

## stackfoundry

This repo's stackfoundry profile is in `.stackfoundry/`: start at `profile.md`; targets and gates are in
`targets.json`, settings in `config.json`.

The rulebooks in `.stackfoundry/rules/` load by themselves when a matching file is read or written (Claude Code from
`.claude/rules/`). Each target's stack is in `.stackfoundry/targets/<target>.md`.

Targets: `cli`, `plugin`. Say "customize <skill>" to change what a stackfoundry skill or agent does here; the
change lives in `.stackfoundry/extensions/`.
